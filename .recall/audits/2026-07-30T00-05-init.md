## Key finding: docs vs code divergence

This codebase is unusually disciplined about `docs/changelog.md` (every
feature landed is logged there accurately, verified against `git log`), but
several *other* docs — AGENTS.md, `docs/roadmap.md`, `docs/api.md`,
`docs/database.md`, `docs/architecture.md` — describe an earlier state of the
access-control model and are missing several since-added schema
columns/tables and an entire storefront/e-commerce feature area. Specifically:

1. **Access control**: AGENTS.md/roadmap.md/api.md describe a fixed
   `owner/admin/manager/cashier/staff` role → capability matrix. The real
   code (`lib/roles.ts`, `db/schema/access.ts`) replaced this with
   `member.role` = only `owner`|`staff`, and a fully custom per-member
   permission set (`member_permission` table). Confirmed via git log
   (`4ec7bf2 feat: fully custom per-user permissions`, after
   `fbf5938 feat: fine-grained role permissions`).
2. **next.config.ts staleTimes**: roadmap.md/architecture.md claim
   `{ dynamic: 0, static: 0 }` ("always refetches"); actual current value is
   `{ dynamic: 30, static: 30 }` (changed in `fea5753 feat: platform org
   impersonation`, docs never updated).
3. **Schema gaps**: `docs/database.md` doesn't mention `client.type`
   (direct/reseller) or the `reseller_link` table (both real, used by
   services/sales.ts and services/public.ts) or `member_permission`.
   `docs/api.md`'s commission rule body omits the real `base` (`line`|
   `margin`) field.
4. **Scope**: AGENTS.md's "Accounting Domain (target)" section doesn't
   mention the storefront/e-commerce feature set (public store, product
   variants + stock, multi-image galleries with per-photo stock and AI
   disclosure, price tiers, store-type custom attributes, priceless reseller
   share links) that now makes up a large fraction of the catalog module.

Per the "code wins" rule, memory nodes record the verified current
behavior and flag exactly where each doc is stale, rather than repeating the
docs' claims.
